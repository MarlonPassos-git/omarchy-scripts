# AGENTS.md

## Scope

This repository stores personal scripts used by Omarchy/Hyprland.

## Structure

- Executable scripts live in `src/`, use the `omarchy-` prefix, and keep an
  explicit language suffix: `.ts`, `.py`, or `.sh`.
- `src/manifest.tsv` is the source of truth for script, title, description, shortcut, and dependencies.
- `scripts/install.sh` installs every command in the manifest.
- `scripts/uninstall.sh` removes every managed keybinding.
- Do not create wrappers in `~/.local/bin` for this project.

## Languages

- Prefer TypeScript modules for application logic and execute `.ts` directly
  with Node.js 24; do not add a build step for these scripts.
- Use Python when its standard library provides a safer system-file integration,
  such as TOML parsing with `tomllib`; add type annotations and keep `.py` visible.
- Bash scripts must use the `.sh` suffix.
- Keep type-checking tools in development dependencies and run `npm run typecheck`.

## Paths

- Do not commit absolute user paths; use `~` in examples.
- Represent home as `~` in documentation.
- Resolve paths in scripts with `$HOME` or the real clone directory.
- Keybindings must be generated by the installer from `src/manifest.tsv`.

## Hyprland

- Do not edit files in `~/.local/share/omarchy`.
- Use `~/.config/hypr/bindings.lua` for personal keybindings.
- Manage project keybindings inside the `-- BEGIN omarchy-scripts` / `-- END omarchy-scripts` block.
- Generate bindings with Quattro's `hl.unbind(...)` and `o.bind(...)` APIs.
- After changing keybindings, run `hyprctl reload` and `hyprctl configerrors`.

## Shell

- Scripts must use `set -euo pipefail`.
- Functions should have one responsibility and stay small.
- Prefer `hyprctl ... -j` with `jq` when reading Hyprland state.
- Avoid destructive commands on persistent paths: `rm`, `dd`, `mkfs`, `sudo`, `systemctl`, `shutdown`, `reboot`.
- `rm` is acceptable only for cleaning temporary files created by `mktemp`.
- If a destructive command is unavoidable, ask for explicit confirmation before implementing it.

## Documentation

- Every new script must appear in `README.md`.
- The command table must list title, description, shortcut, script, and dependencies.
- Record only user-facing script changes in `CHANGELOG.md`: behavior, install/uninstall, shortcuts, dependencies, and script-owned config. Exclude docs, tests, instructions, changelog maintenance, and internal refactors.
- Group by `YYYY-MM-DD` as the release identifier; no commits or version numbers.
- Merge same-day work into concise Added, Changed, and Removed sections.
- Add code comments only for risks, decisions, and non-obvious side effects.

## Validation

- Run `bash -n <script>` after editing shell scripts.
- Run `./scripts/install.sh` after changing the manifest or installer.
- Run `./scripts/uninstall.sh` after changing uninstall logic.
